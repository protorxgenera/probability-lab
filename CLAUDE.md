# probability-lab

Interactive learning environment for probability in an ML master's course (UPB, Robotics & Automation).
Goal: build intuition through **predict → simulate → derive → verify → explain**.
Full study plan: `../probability-for-ml-plan.md`.

## Repo layout

```
CLAUDE.md
pyproject.toml / uv.lock   ← Python env (uv). Run things with `uv run ...`
notebooks/                 ← Jupyter lessons, one folder per module (01-foundations/, ...)
exercises/                 ← markdown problem sets + hidden solutions
notes/                     ← one-page summaries per module
scripts/                   ← Python helpers, e.g. export_fixtures.py
lab/                       ← the web app (pnpm, own package.json)
  src/math/                ← Ben's math functions + their tests
  src/widgets/             ← one widget per concept
  src/components/          ← shared widget shell + shadcn/ui components
  fixtures/                ← reference values exported from scipy (JSON)
```

## Lab stack

- Vite + React + TypeScript, Tailwind CSS, **shadcn/ui** for all UI (add components with `pnpm dlx shadcn@latest add <name>`)
- three.js for 3D widgets, GSAP (`@gsap/react` / `useGSAP`) for animation
- 2D plots in SVG or canvas
- Vitest for tests
- Package manager: **pnpm** (never npm/yarn). Python: **uv** (never pip).

## Rules

1. **Never implement anything in `lab/src/math/` unless Ben explicitly asks.** Ben writes the math.
   You may write tests that compare its output to reference values in `lab/fixtures/`
   (generated by `uv run scripts/export_fixtures.py` using scipy), and you may write
   function signatures + docstrings as specs when asked.
2. `src/math/` stays framework-free: pure TypeScript functions, no React imports.
   Widgets import from it; randomness takes a seedable RNG argument.
3. **Never reveal solutions** to anything in `exercises/`, and don't fill in derivations
   or "PREDICT" cells in notebooks unless asked.
4. Every widget must have:
   - a **prediction input** (slider/field) set *before* the reveal
   - a **simulate / reveal** step
   - a **live formula** display that updates with the parameters
   - a one-line **"what to notice"**
5. Progress tracking in localStorage (wrapped in try/catch): modules done, checkpoint status,
   prediction accuracy.
6. Design: use shadcn/ui components and its theme tokens; keep it calm and typographic.
   Avoid generic AI-looking gradients, glows and emoji. Support light and dark mode.
7. Keep changes small and explain what you did — Ben is learning; prefer readable code over clever code.

## Tutoring style (when asked about the math)

Socratic: hints before answers, find the first error instead of rewriting everything,
always push the predict → simulate → derive → verify → explain loop.
